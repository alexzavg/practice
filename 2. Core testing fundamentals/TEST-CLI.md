# Test Execution & CLI

Справочник по запуску тестов из командной строки. Все команды проверены
в этом репозитории: Node v22.0.0, Jest 30, Mocha 10, Jasmine 5, c8 10.

Общее правило: раннер ищет файлы по конфигу, а не угадывает. Конфиги здесь —
`jest.config.js`, `.mocharc.json`, `2. Core testing fundamentals/jasmine/jasmine.json`.

---

## 1. Запуск всего набора

| Раннер  | Команда npm            | Что под капотом                                                        |
| ------- | ---------------------- | ---------------------------------------------------------------------- |
| Jest    | `npm run test:jest`    | `jest`                                                                 |
| Mocha   | `npm run test:mocha`   | `mocha`                                                                |
| Jasmine | `npm run test:jasmine` | `jasmine --config="2. Core testing fundamentals/jasmine/jasmine.json"` |
| все три | `npm test`             | последовательно, через `&&`                                            |

Тезисы:

- `npm test` останавливается на первом упавшем раннере: `&&` не выполнит
  следующую команду после ненулевого кода возврата.
- Код возврата — главный контракт с CI: `0` — успех, не `0` — падение.
- Все три раннера ищут файлы по своему конфигу, поэтому Jest не подхватывает
  спеки Mocha, а Mocha — тесты Jest.

## 2. Запуск одного файла

```bash
npx jest "2. Core testing fundamentals/jest/5_skip.test.js"
npx mocha "2. Core testing fundamentals/mocha/2_hooks.spec.js"
npx jasmine --config="2. Core testing fundamentals/jasmine/jasmine.json" --filter="Корзина"
```

Тезисы:

- Jest принимает не путь, а **регулярное выражение по пути**, поэтому
  `npx jest skip` запустит все файлы, в имени которых есть `skip`.
- Mocha принимает обычный путь или glob-маску, она перекрывает `spec`
  из `.mocharc.json`.
- Jasmine путь в аргументе игнорирует: список файлов берётся из `jasmine.json`.
  Для сужения есть `--filter` по имени теста или `--filter-path` по пути
  в дереве блоков.
- Пути здесь с пробелами (`2. Core testing fundamentals`), поэтому кавычки
  обязательны.

## 3. Запуск конкретного теста по имени

```bash
npx jest -t "складывает"                                        # подстрока имени
npx mocha --grep "складывает"                                   # регулярное выражение
npx jasmine --config="...jasmine.json" --filter="складывает"    # регулярное выражение
```

Тезисы:

- Jest `-t` (`--testNamePattern`) сопоставляет **полное склеенное имя**:
  `describe > describe > it`. Поэтому `-t "Калькулятор"` запустит весь блок.
- Mocha `--grep` ищет по тому же склеенному имени; инверсия — `--invert`.
- Jasmine `--filter` работает так же, но без инверсии.
- Фильтр по имени лучше, чем `only` в коде: ничего не нужно править
  и нечего забыть закоммитить.
- Файл всё равно загружается целиком, просто неподходящие тесты помечаются
  пропущенными.

## 4. Watch mode

```bash
npm run test:jest:watch       # jest --watch
npm run test:mocha:watch      # mocha --watch
npm run test:jasmine:watch    # nodemon --watch "2. Core testing fundamentals" --ext js --exec "npm run test:jasmine"
```

Тезисы:

- Watch перезапускает тесты при сохранении файла. Это режим для разработки,
  в CI он не используется никогда: процесс не завершается.
- `jest --watch` гоняет только тесты, затронутые изменениями, и требует git.
  Если репозиторий не инициализирован, нужен `--watchAll`.
- В интерактивном режиме Jest принимает клавиши: `p` — фильтр по имени файла,
  `t` — по имени теста, `f` — только упавшие, `q` — выход.
- `mocha --watch` перезапускает весь набор целиком, без интерактивных клавиш.
- У Jasmine своего watch нет. Здесь он собран из `nodemon`: тот следит
  за `.js` в папке и перезапускает команду.

## 5. Покрытие кода (coverage)

```bash
npm run test:jest:coverage        # jest --coverage
npm run test:mocha:coverage       # c8 mocha
npm run test:jasmine:coverage     # c8 npm run test:jasmine
```

Пример отчёта:

```
File           | % Stmts | % Branch | % Funcs | % Lines | Uncovered Line #s
 calculator.js |   84.84 |    66.66 |     100 |   84.84 | 20,27-30
```

Тезисы:

- Покрытие из коробки есть только у Jest. Mocha и Jasmine оборачивают в `c8`
  (движок V8) или `nyc`.
- Четыре метрики: `Stmts` — инструкции, `Branch` — ветки `if`/`switch`/`?:`,
  `Funcs` — функции, `Lines` — строки.
- Самая полезная колонка — `Uncovered Line #s`: конкретные строки, куда
  тесты не дошли.
- Считается по исходному коду, а не по тестам. Проверяемый код держат
  в отдельном модуле — здесь `src/calculator.js`. Что попадает в отчёт,
  задано в `collectCoverageFrom` (Jest) и `include` в `.c8rc.json` (c8).
- Высокий процент не значит, что тесты хорошие: строка может выполниться
  без единой проверки результата.
- Порог можно сделать жёстким: `coverageThreshold` в конфиге Jest или
  `c8 --lines 80 --branches 70`. Тогда низкое покрытие роняет прогон.
- Папка `coverage/` в `.gitignore` — отчёт генерируется, а не хранится.

## 6. Полезные флаги для CI

| Задача                         | Jest          | Mocha           | Jasmine       |
| ------------------------------ | ------------- | --------------- | ------------- |
| остановиться на первом падении | `--bail`      | `--bail`        | `--fail-fast` |
| запретить забытый `only`       | —             | `--forbid-only` | —             |
| выключить параллелизм          | `--runInBand` | по умолчанию    | по умолчанию  |
| убрать цвет в логах            | `--no-colors` | `--no-color`    | `--no-color`  |
| машиночитаемый отчёт           | `--reporters` | `--reporter`    | `--reporter`  |
| список тестов без запуска      | `--listTests` | `--dry-run`     | —             |

Тезисы:

- `--forbid-only` в Mocha — защита от забытого `it.only`: прогон упадёт,
  а не выключит остальные тесты молча. У Jest и Jasmine аналога нет,
  это закрывают правилом ESLint `no-focused-tests`.
- Jest по умолчанию распараллеливает файлы по воркерам. `--runInBand`
  нужен при отладке и при общем внешнем ресурсе, например одной базе.
- В CI почти всегда добавляют `--ci` (Jest): он не создаёт новые снапшоты
  молча, а роняет прогон.
- У Jasmine есть команда `enumerate`, но в этой конфигурации она возвращает
  пустой список `[]`, поэтому в таблице стоит прочерк.
